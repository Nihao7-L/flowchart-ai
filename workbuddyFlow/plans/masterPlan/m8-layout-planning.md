# m8 — 布局规划（排版 + 走线）

> 状态：**进行中**（2026-09-18 用户拍板「都按推荐来」）
> 模块编号说明：**M 号是身份（登记号），S 号是时间（执行序）** —— 本模块 M8 的编号早于 M9（契约容量），但按 S 序 **S1a（M9）先行、S1b（M8）随后**，因为排版需要 `group` 语义作输入。

> 触发来源：`roadmap.md` 第七节（两个缺失的步骤）

## 一、目标

把「怎么摆」从"一次性几何求解"升级为**先规划、后落地**：

1. **排版（v2-39）**：复杂需求先做**结构规划**（模块 → 模块成员 → 模块间关系），再按分区落几何 —— 让复杂图的标签压叠归零、模块结构在画布上可见、`frame` 与内容对齐；
2. **走线（v2-41，待立）**：线条不只是直线 —— 长边可绕行、可折线，摆脱"每层居中叠罗汉"逼出来的长斜线。

一句话验收（排版）：**同一句"画一个多层微服务架构图"，排版后标签压节点 = 0，且能一眼看出模块分区。**

## 二、边界

- **允许新增**：`graph/ScenePlanner.java`（排版层，纯函数式、异常一律原样返回）；带模块的基准 fixture；分区/布局/契约的测试。
- **允许修改**：`schemas/scene.schema.json`（`shape.group` + `frame.children` 两个**可选**字段）；`service/PromptService.java`（复杂图的分组要求）；`service/GenerationService.java`（链路接入）；`graph/LayoutSpec.java`（间距对称化）；前端 `sceneAdapter.ts` 白名单与 `children` 透传。
- **禁止改动**：
  - ❌ **不碰 `frame` 的 `children` 取舍动机** —— "不让 LLM 填"不变（09-17 拍板）；改的是**落法**：后端算成员、适配层填（09-18 实测确认 `children` 是框↔内容归属的唯一途径）；
  - ❌ **不碰绑定箭头策略** —— "线怎么画"归本模块的走线子计划（v2-41），排版只管"节点怎么摆"；
  - ❌ **不碰编辑模式的坐标冻结语义** —— 既有图形坐标一个不许动（v2-37 `SceneDrift` 的判据），编辑模式下排版一律走原路径；
  - ❌ **不给"小图"引入任何行为变化** —— 图形数 ≤ 12 时完全走今天的路径。

## 三、分层边界

改动落在 `graph/`（新增排版层，位于 `SceneDeduper` 与 `LayoutEngine` 之间）与 `service/`（提示词、链路编排），**不触碰** `client/`、`session/`、`controller/`。

切法理由：排版是**纯几何/拓扑决策**，输入输出都是场景 JSON —— 放在 `graph/` 才能让两个 `LayoutEngine` 实现共享它，也能被基准工具单独调用。

### 5.0 一个口径修正（2026-09-18 实施后回填）

`v2-39` 计划书里 5.2 写的是"模块从哪来：LLM 为主 + **后端聚类兜底**"，实际交付时**兜底多了一条守卫**：场景里存在 `frame` 时不启用聚类兜底。原因：兜底只能聚出「模块1」这类**无名**模块，而 frame 是按 `name` 认领的 —— 认领不上就原样不动，于是节点被搬离 LLM 给的框，正好加重 5.4 实测的病症（24/42 个图形跑出框）。这条守卫及其替代路径（提示词要求 frame 的 name 与模块名逐字相同）写在 `ScenePlanner#inferGroups` 的 javadoc 里，并由 `ScenePlannerTest#inferenceIsSkippedWhenFramesExist` 锁定。

### 5.1 为什么走线要等排版

09-18 实测确认：Excalidraw 0.18.1 里**绑定箭头 ⇔ 直线**；要做折线只能"箭头不绑定 + 后端算走行点"，代价是拖节点时箭头不跟随，需在 `PUT /api/model/canvas` 回写链路补重新路由。而"走哪条路"取决于"哪里有空地"——**排版决定空地，走线决定路径**，顺序不能倒。

## 六、验收口径（模块级）

1. 复杂图的标签压叠归零（基准 + 真实 LLM 双口径）；
2. `frame` 与内容对齐：框两两重叠 = 0、跑出所属框的图形 = 0、落进多框的图形 = 0（现状 5 / 24 / 6）；
3. 小图与编辑模式**零回归**（坐标逐元素一致）；
4. 门禁全绿：后端测试 + checkstyle 0 违规 + 前端三绿 + 冒烟 + E2E。

## 七、覆盖测试数据（模块级）
