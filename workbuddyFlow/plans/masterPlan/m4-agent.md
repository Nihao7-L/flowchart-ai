## 目标
把"伪 ReAct（只有计划没有观察回环）"换成真 ReAct：每步 Thought→Action→Observation 必须回喂 LLM 再决策。

## 边界

- 允许修改：`service` 编排（接入 agent 主循环）

## 分层边界
落在 `agent/`；编排 `tools` / `llm` / `graph`。不触碰 `session`（M5）与前端（M6）。原因：Agent 是"大脑"，编排既有能力，不改底层。

## 上下文注入与意图分类（设计要点）

> 设计基线：**方案 A**——意图分类吸收进 ReAct 的 Thought，与主 LLM 同一次调用；不另设独立分类器模块。（方案 B：前置便宜小模型/规则做粗路由，列为待决策优化项，默认不启用。）

### 意图分类（四个子判断）
每轮 Agent 在 Thought 内部完成四步判断，不独立成模块：
1. **意图是什么**：问知识 / 要干活 / 写代码 / 画图 / 改文件？
2. **信息够不够**：不足 → 先反问澄清（琥珀色分支），不强行回答。
3. **要不要工具**：纯聊天能答的不调；涉实时事实 / 文件 / 多步任务 → 路由出去。
4. **走哪条分支**：事实→搜索、文件→读、多步→建任务、专业→加载技能、可答→直接给、重操作→先问。

### 上下文注入（最小集 + 迭代回填）
- 模型无状态：每轮由 `service/` 重拼 `messages[]` 一次性发给主 LLM，分类与 Action 在同一次调用内完成。
- **最小上下文集（首迭代）** = 静态 `system`（角色 / 规则 / **工具清单**）+ 当前轮用户消息。**不是空集**——工具清单常驻 system 是分类的"源索引"，缺它模型不知有哪些源可选。
- 迭代回填：RAG 片段、折叠历史、工具结果在取数之后回喂下一轮迭代，不在首轮出现。
- 口径统一："单次 LLM 调用" = 每轮迭代一次（一个回合可循环 N 次，每次重拼完整 messages）。

### 责任归属
- 分类（模糊推理）：主 LLM 在 Thought 中完成。
- 相关性打分 / 取数（确定活）：`rag/`（embedding + reranker）与 `tools/` 执行，不归 LLM。
- LLM 只提议（tool_calls），`service/` 编排代码去执行（读文件 / 取数 / 落库）。

### 成本护栏（ADR 钩子）
默认方案 A 不引入额外分类器。仅在延迟 / 成本敏感时，可后续评估方案 B（前置便宜小模型 / 规则做粗路由）作为优化项——本计划不默认启用，列为待决策点。

## 验收口径
1. 不变式 4：每步 Observation 必须回喂 LLM（单测可断言）
2. 步数达上限或中断时优雅停止并产出 partial 结果
3. v2-20 用例端到端跑通，事件流完整

## 覆盖测试数据
| 场景 | 输入 | 期望 |

| 边界 | 故意让工具连续失败 | 步数上限触发，输出 partial + 记 tech-debt |
