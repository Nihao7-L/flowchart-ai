> 模块状态：**进行中**（子计划 v2-40 已开工，P0 落地中）
> 建立：2026-09-18（用户拍板「新开 m9」，不并入已归档的 M1）

## 一、这个模块要解决什么

用户判断（2026-09-18 原话）：

> 「画不了复杂的图形我觉得 scene.schema.json 还有这个原因，这个太过于局限了，这个太过于死板了，
> 就算现在再怎么测试都没用」
> 「后端可以生成什么我觉得可以看看前端这个 Excalidraw 可以渲染什么东西」

**实测成立**：渲染器侧能力（10 类元素 / 12 种箭头端点 / 多层 `groupIds` / 可嵌套 `frame` /
圆角 / 图形虚线 / `verticalAlign` / `link` / 多段折线）**远超契约**（6 类可用元素 / 约 30 个字段）。
**"复杂图画不出来"的根因不在渲染器，在契约自己画的圈。**

而这圈有两道闸门，**只改一道等于没改**（`constraint.md` 已立为红线）：

| # | 闸门 | 位置 | 漏改的症状 |
|---|---|---|---|
| 1 | 契约（给 LLM 的说明书） | `src/main/resources/schemas/scene.schema.json` | LLM 不知道能用 → 永远不产出 |
| 2 | 前端白名单 | `frontend/src/lib/sceneAdapter.ts` 的 `SKELETON_KEYS` | 产出了也被**静默丢弃** → "改了没反应" |
| 3 | 校验器枚举 | `graph/GraphValidator.java` 的 `FILL_STYLES` / `ARROWHEADS` 等 | LLM 用新枚举值 → 判非法 → 白耗一整轮重试（约 130 秒） |

## 二、边界（模块级）

- **允许新增**：契约字段（全部可选）· `frontend/src/types.ts` 的类型 · 校验器枚举与规则 ·
  语义→视觉映射表（"定规范"的实体）· 图型语法约束（进提示词）
- **允许修改**：`PromptService` 的作图规则段 · `SceneAdapter` 的适配补丁 · 布局引擎对非图形图的处理
- **禁止改动**：
  - ❌ **不把几何责任交给 LLM**：`x` / `y` 仍是种子值，布局由后端算
  - ❌ **不破坏现有 6 类元素的语义**：新增字段全可选，旧场景 JSON 必须原样能渲染（回归锁）
  - ❌ **不把 `children` 交给 LLM 填**（2026-09-17 动机不变）；但落法改为"后端算、适配层填"
  - ❌ **不碰 `SceneDrift` / 编辑模式坐标冻结语义**（否则与 v2-37 打架）
  - ❌ **不把 Excalidraw 字段直接开给 LLM**（决定了"语义编译"路线，见第六节）

## 三、分层边界

| 层 | 包 / 文件 | 本模块的改动 |
|---|---|---|
| 契约层 | `src/main/resources/schemas/` | 字段扩展（唯一真相源） |
| 校验层 | `graph/GraphValidator` | 枚举白名单同步（**最容易漏的一层**） |
| 语义层 | 新（拟 `service/` 或 `semantics/`） | 语义 → 视觉映射表（v2-41 拟建） |
| 布局层 | `graph/ElkLayoutEngine` | 对"无图形元素"的图也要生效 |
| 适配层 | `frontend/src/lib/sceneAdapter.ts` | 白名单 + frame 成员填充 |
| 提示词层 | `service/PromptService` | 图型语法、样式字段禁用说明 |

### 6.1 三类优先图型的缺口性质（**三类完全不同，不能当成一件事做**）

| 图型 | 缺的能力 | 落在哪个子计划 | 难度 |
|---|---|---|---|
| **部署图** | 嵌套集群：多层 `groupIds` + 容器虚线框 + 分区布局 | v2-40 的 **P1（层次）**＋ v2-39 的排版 | 中（地基已有，缺编排） |
| **决策树** | 分支标签避让 + 子决策组嵌套 | **布局层**（`SIBLING_GAP` 写死 80 是直接原因）＋ 走线（长边标签） | 中（是布局问题，不是契约问题） |
| **甘特图** | **时间轴 + 任务条**——契约里根本没有"条"这个原语 | v2-40 的 **P3（图型语法）**，需要**新增语义原语** | **高（三类里唯一需要新原语的）** |

> ⚠️ **提示**：甘特图不是"多一个字段"能解决的。Excalidraw 也没有甘特原语，
> 只能用圆角矩形近似 + 时间轴刻度（`line` + `text`）。
> 要先定"甘特图在我们的系统里长什么样"（语义原语 + 视觉映射），再谈落地。

## 七、验收口径（模块级）

1. **契约字段可用的三处同步**：契约 + `SKELETON_KEYS` + `GraphValidator` —— 由冒烟的自动守卫用例锁住
2. **旧场景零回归**：改动前的场景 JSON 渲染结果逐元素一致
3. **§6.1 三类图型各有一张真实 LLM 出图**，肉眼 + 指标双确认
4. **每条图型有语法约束进提示词**（允许的元素组合 / 必需元素 / 布局模式）
5. **门禁全绿**：后端测试 + checkstyle 0 违规 + 前端三绿 + 冒烟 + E2E
