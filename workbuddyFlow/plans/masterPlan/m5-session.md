- 模块编号：M5

## 目标
把 M1（S1）交付的**内存版 session** 升级为**可持久化**：`SessionStore` 的 Redis 实现 + 探活自动降级，并提供恢复 / 历史列表 API。**不再包含"从零做抽象"**——接口与内存实现已在 M1 落地。

## 边界
- 允许新增：`session/` 包的 **Redis 实现**与探活降级切换；恢复 / 历史 API
- 允许复用：M1 已落地的 `SessionStore` 接口与内存实现（本模块只加实现，不改接口语义）
- 允许修改：`controller`（新增恢复 / 历史 API）
- 禁止改动：生成链路（M1）、Agent（M4）

## 分层边界
落在 `session/`；被 `controller` / `service` / `agent` 调用，不反向依赖业务包。原因：会话是横切基础设施，必须被任意层复用而不被业务污染。

## 前置
- **M1 v2-11 已交付内存版 session**（`SessionStore` 接口 + 内存实现 + 坐标回写入口），且自 S1 起已在真实链路里跑（多轮对话 + 人拖拽回写）
- M4 已把 IR 作为核心数据结构
- Redis 可选依赖可用（不可用时降级内存，见 `constraint.md` 资源约束）

## 步骤
1. v2-21 `SessionStore` 的 Redis 实现 + 探活自动降级切换（接口与内存实现在 M1 已就位）
2. v2-22 会话恢复 / 历史列表 API

## 验收口径
1. Redis 可用时写入并可读回；不可用时自动降级内存不报错
2. 重启后能从 session 恢复 model（IR）
3. 历史列表 API 返回该用户会话清单
4. 降级切换对上层透明：同一套接口在 Redis / 内存两种后端下行为一致
