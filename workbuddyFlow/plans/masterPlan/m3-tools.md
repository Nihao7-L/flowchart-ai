## 元信息

## 目标
把"Diagram Tools = 自研 MCP"做成真工具注册/执行体系：LLM 选工具 → 后端执行 → 结果回灌再推理。

## 边界
- 允许新增：`tools/` 包（Tool 接口、ToolRegistry、ToolExecutor）
- 允许修改：`service` / `llm` 调用（接入 tool calling）
- 禁止改动：前端渲染（M6）、会话层（M5）

## 分层边界
落在 `tools/`；向下调 `rag` / `llm`，被 `agent` 在阶段4 调用。原因：工具是 Agent 的执行手脚，先独立做好再被编排。

## 前置
- M1 出图链路可用
- `llm/` 支持 function calling / tool calling

## 步骤
1. v2-15 Tool 接口 + 注册表（新工具 = 加一个类，零改动核心）
2. v2-16 执行器：LLM 选工具 → 后端执行 → 结果并入素材
3. v2-17 结果回灌一轮：工具结果回喂 LLM 再推理（上一轮明确没做的闭环）

## 验收口径
1. 新增工具只需实现接口并注册，不改执行器主流程
2. LLM 选定工具后后端能真实执行并返回结构化结果
3. 工具结果参与下一轮 LLM 决策（非一次性丢弃）

## 覆盖测试数据

|---|---|---|

| 异常 | 工具执行抛错 | 错误被捕获并作为 observation 回喂，不崩溃 |
