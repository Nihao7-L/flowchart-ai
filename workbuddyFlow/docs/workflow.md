# workflow.md — 自反馈机制

> 只回答一个问题：**系统跑起来后，怎么知道自己做得好不好，并自动修正。**
> 缺下面任一条，就是装饰。

## 一、信号源（反馈从哪来）

- **run-verify 输出**：编译/单测/前端检查通过率（每次执行必跑）。
- **graph 校验 issues**：出图结构化校验的 field/reason/hint 明细。
- **用户显式反馈**：聊天中对"图不好看/换复杂的"等指令即修正信号。
- **人工抽检**：人读 `activeLog.md` 复盘执行质量。
- **真实 LLM 端到端出图**（2026-09-18 建）：`tools/e2e/e2e_real_llm_layout.py`（新建 + 编辑两轮，断言零 NaN / 零重叠 / 既有坐标冻结）；**复杂提示词电池** `tools/e2e/e2e_prompt_battery.py`（9 条题，512~2570 字，产出指标报表 + 场景快照）。
- **探针**（零 LLM 消耗，秒级）：`tools/e2e/probe_*.py` —— 契约容量 / 文字宽度 / frame 归属 / frame 逃逸 / 折线箭头。回答的是"事实是什么"，不是"这次做得好不好"。
- **布局量化基线**（2026-09-18 建）：`tools/layout-bench/`（重叠 / 交叉 / 长宽比 / 标签遮挡 / 包围盒），用于引擎选型与回归对比。
- **回归锁**：`ScenePlannerTest#framesDoNotOverlap` / `#frameFollowsItsModule`（v2-39 病症回归）、`scene-smoke.mjs` 末尾的契约↔白名单**双向差集**守卫。

## 二、判断标准与阈值（什么算好/差，必须有数值）

第一梯队 = 门禁（自动，红灯即失败）：

| 指标 | 好 | 差（触发动作） |
|---|---|---|
| run-verify 退出码 | 0（VERIFY PASS） | 非 0（VERIFY FAIL）→ 自动修 |
| 后端单测 / checkstyle | 153 全过 / 0 违规 | 任一失败 → 自动修 |
| 前端 tsc + eslint + vite | 三绿 | 任一红 → 自动修 |
| 适配层冒烟 | 16/16 | 任一失败 → 自动修 |

第二梯队 = 出图质量（2026-09-18 起有明确口径，靠电池与探针读）：

| 指标 | 好 | 差（触发动作） |
|---|---|---|
| 图形重叠对数 | 0 | >0 → 判缺陷（布局/吸附问题） |
| 坐标为 NaN | 0 | >0 → 判缺陷（适配层缺几何） |
| 图形跑出所属 frame（`shapesEscapingOwnFrame`） | 0 | >0 → 判缺陷；**注意**要区分"模块合法无框"（正常）与真逃逸 |
| frame 落网格 / 框两两重叠 | 3/3 · 0 | 不达标 → 布局未覆盖 frame |
| 边标签压叠对数 | 越少越好（基准图 2） | 明显升高 → 排版问题（非间距问题） |
| 单次出图校验轮数 | 1 轮通过 | ≥3 轮仍不过 → 升级人工（且预算会被吃光，见三） |

> 注：延迟 P99/QPS、单测覆盖率等运行时指标当前**仍未埋点**，列为待建（infra 阶段 v2-27+）。

## 三、触发动作（偏差出现后干什么）

- **自动重试**：校验不过 → 带 issues 重调 LLM，≤3 轮（闭环自动，不問人）。
  - ⚠️ **已知低效点（2026-09-18 复放坐实）**：像**自环箭头**（`start.id == end.id`）这类**结构性非法**，重试**不会变好** —— 同元素名会在下一轮原样复现，白烧一轮预算（单轮上限 300s、总预算 420s，两轮失败就必然撞墙）。正确做法应是**结构修复（在 binder/校验前直接丢弃或改写该元素）**，而不是重试。当前仍是重试，改法待定。
  - ⚠️ 附带缺口：**校验失败的明细（field/reason/hint）目前不落日志**，只存在于 SSE 的 `validation` 事件里 → 事后只能靠回放工具（`ReplayValidation`，`-Dpayload=<失败载荷>`）反查。这是排查"为什么重试"最缺的一环。
- **自动修**：run-verify FAIL → Agent 看输出自改，不阻断用户。
- **降级**：token 超阈值 / LLM 超时 → 降级小模型或返回部分结果。
- **写回知识库**：产品 Agent 缺陷 → 升格为 `plans/masterPlan/` 下的路线图任务。
- **告警给人**：重大越界（如 Agent 误改 env/系统设置）→ 立即告警用户，不自动处理。

## 四、消费者（给人看，还是驱动程序自调）

- **自动闭环（程序自调）**：校验重试、run-verify 自修、token 降级——无需人介入。
- **人审（给人看）**：`activeLog.md`（执行证据）、run-verify 报告——由用户评审与决策升格。
- 设计原则：能自动的自动，需判断的交人；所有自动动作留痕供人回溯。

## 五、闭环节奏与效果度量

- **节奏**：每次执行 → 必跑 run-verify + 追加 `activeLog.md` 一行（带证据）；每阶段收尾 → 复盘 `plans/masterPlan/` 任务状态决定修或升格；涉及出图质量 → 再跑 真实 LLM E2E / 电池 / 探针 中的一层。
- **效果度量（当前可量化项）**：verify 绿率（PASS/总执行）、校验平均轮数（越低越好）、缺陷升格数（产品缺陷 → 路线图升格数）、电池报表里的重叠/逃逸/网格指标。
- **已知缺口**：
  1. 电池**不做 PASS/FAIL、只记事实**（改前 5/24/6 这类数字要靠人对照）→ 闭环仍是**半自动**，人必须读报表。
  2. 电池耗时长（98~283 秒/题）且**烧真实 token**，无法每次改动都跑 → 目前只在收尾验收时抽题跑。
  3. 无运行时指标埋点（延迟/成本/轮数分布）—— v2-27 可观测要补。
- 结论：闭环已从"纯人工外置记忆"升级为"**门禁自动 + 质量半自动**"，但离系统级自动学习仍差一步（电池门禁化 + 指标埋点）。

## 六、与评测集 + 回归测试绑定（硬要求）

每次改动前后跑同一批固定用例，比对**通过率**与**成本**。没有度量，闭环就只是流程图上的一个圈。
当前状态（2026-09-18）：评测集**已建** —— 题源 `docs/复杂提示词测试集.md`（9 条），执行器 `tools/e2e/e2e_prompt_battery.py`，配套探针与布局基准；门禁（run-verify，153 测试 + 前端三绿 + 冒烟）已全自动。
下一步（未做）：把电池的硬指标（NaN / 图形重叠 / frame 逃逸）接成**电池门禁**、并支持 `--seed` 复现与历史对比，才算真正闭环到"改编即跑"。
