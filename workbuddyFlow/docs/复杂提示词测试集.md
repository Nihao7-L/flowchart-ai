## 二、流程图（嵌套子流程）

### 提示词 2：电商订单处理全流程（含嵌套子流程）
```
设计一个电商订单处理流程图，要求包含多个嵌套子流程，整体流程如下：

主流程：
1. 用户下单 → 2. 库存检查 → 3. 支付处理 → 4. 订单确认 → 5. 物流处理 → 6. 订单完成

嵌套子流程1：库存检查（菱形判断节点）
   ├── 检查库存
   ├── 判断：库存是否充足？
   │   ├── 是 → 锁定库存 → 继续主流程
   │   └── 否 → 判断：是否允许缺货预订？
   │       ├── 是 → 创建缺货订单 → 通知供应商 → 等待补货
   │       └── 否 → 提示库存不足 → 推荐替代商品 → 结束
   └── 锁定失败处理

嵌套子流程2：支付处理（多分支）
   ├── 选择支付方式
   │   ├── 支付宝支付
   │   │   ├── 生成支付链接
   │   │   ├── 调用支付宝API
   │   │   ├── 等待回调
   │   │   └── 验证签名
   │   ├── 微信支付
   │   │   ├── 生成预付单
   │   │   ├── 调用微信API

   │       └── 短信验证
   ├── 支付结果处理
   │   ├── 成功 → 更新订单状态 → 发送通知
   │   ├── 失败 → 判断：是否重试？
   │   │   ├── 是 → 重新选择支付方式
   │   │   └── 否 → 取消订单 → 释放库存
   │   └── 超时 → 定时任务检查 → 自动关闭
   └── 异常处理

   │   └── 异常签收 → 客服介入

- 主流程用粗实线

- 判断节点用菱形
```

## 四、时序图（嵌套循环）

### 提示词 4：复杂用户登录时序图（含嵌套循环和并行）
```
设计一个复杂的用户登录时序图，包含嵌套循环和并行交互：

参与者（8个）：
1. 用户 (User)
2. 前端 (Frontend)
3. API 网关 (API Gateway)
4. 认证服务 (Auth Service)
5. 用户服务 (User Service)
6. 缓存服务 (Redis)
7. 数据库 (Database)
8. 日志服务 (Log Service)

主流程：
1. 用户 → 前端：输入用户名密码
2. 前端 → API网关：POST /api/login
3. API网关 → 认证服务：转发请求

嵌套循环1：用户验证（最多3次）
   loop 登录尝试次数 < 3
     4. 认证服务 → 数据库：查询用户
     5. 数据库 → 认证服务：返回用户信息
     6. alt 用户存在
        7. 认证服务 → 认证服务：验证密码
        8. alt 密码正确
           9. 认证服务 → 缓存服务：生成Token
           10. 缓存服务 → 认证服务：Token已存储
           11. 认证服务 → 日志服务：记录登录成功
           12. break 退出循环
        else 密码错误
           13. 认证服务 → 认证服务：记录失败次数
           14. 认证服务 → 前端：返回错误（剩余次数）
        end
     else 用户不存在
        15. 认证服务 → 前端：返回"用户不存在"
        16. break 退出循环
     end
   end

并行交互：多因素认证（可选）
   par 手机验证码
     17. 认证服务 → 用户：发送短信验证码
     18. 用户 → 前端：输入验证码
     19. 前端 → 认证服务：提交验证码
   and 邮箱验证码
     20. 认证服务 → 用户：发送邮箱验证码
     21. 用户 → 前端：输入验证码
     22. 前端 → 认证服务：提交验证码
   end

嵌套循环2：Token刷新
   loop Token有效期 < 30分钟
     23. 前端 → API网关：携带Token请求
     24. API网关 → 认证服务：验证Token
     25. alt Token有效
        26. 认证服务 → API网关：验证通过
        27. API网关 → 前端：返回数据
     else Token即将过期
        28. 认证服务 → 缓存服务：刷新Token
        29. 缓存服务 → 认证服务：新Token
        30. 认证服务 → 前端：返回数据 + 新Token
     end
   end

异常处理：
- 网络超时 → 重试机制
- 服务不可用 → 降级策略
- 账户锁定 → 管理员解锁

视觉要求：
- 生命线用垂直虚线
- 激活条用矩形
- 循环用loop框
- 条件用alt/else框
- 并行用par框
- 异常用红色标注
```

## 使用建议

1. **复杂度**：每个提示词都包含多层嵌套和复杂逻辑
2. **结合图**：测试FlowAI处理多种图表类型结合的能力
3. **验证重点**：检查嵌套结构是否正确、逻辑是否完整、布局是否清晰
4. **性能测试**：这些复杂图表可能需要较长生成时间
