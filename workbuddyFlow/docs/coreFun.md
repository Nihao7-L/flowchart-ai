# coreFun.md — 核心功能

> 只回答一个问题：**系统能做什么、不能做什么、给谁用。**
> 读它的时机：接任务前（确认边界归属）、验收时（确认是否真做完）。

## 一、核心能力（3~5 条，每条对应架构模块）

1. **自然语言出图（NL → IR）**：用户输入自然语言 → 后端组装 Prompt 调 LLM → 产出结构化图 JSON（IR，无坐标）→ 校验 → 渲染。对应模块：`controller` / `service` / `llm` / `graph`。
2. **双通道协作白板**：人类在画布拖拽/手绘 与 AI 聊天命令改图，二者改同一份图状态。对应模块：前端 `@excalidraw/excalidraw` 白板 + 后端 `session`（持有 model）+ `POST /api/chat`。
3. **Agent 自主改图（ReAct + Diagram Tools 自研 MCP）**：复杂意图下 agent 走 Thought→Action(tools)→Observation 循环，工具（add / connect / update / delete / generate_full）直接改后端 model。对应模块：`agent` / `tools` / `service`。
4. **校验与自修正**：图结构校验带 field / reason / hint，不通过带 issues 重调，最多 3 轮。对应模块：`graph`（GraphValidator）。
5. **会话记忆与多轮上下文**：按会话持久化消息与 model 状态（Redis 优先，降级内存）。对应模块：`session`。

## 二、非目标（Non-goals，必写）

- 不做代码生成 / 代码图反向工程
- 不做"图片识别转图"（OCR → diagram）
- 不做多租户 SaaS / 账号体系
- 不引入需专人运维的中间件（如 Victoria / Vector 观测栈、独立消息队列）
- 不做离线批处理大图（当前面向交互式单/少用户）

## 三、能力量级（谁在用、多频繁、峰值多大）

| 能力 | 使用者 | 频率 | 峰值/规模 | 当前实测 |
|---|---|---|---|---|
| NL 出图 | 终端用户 | 每次对话 1 次 | 设计目标并发见架构；当前单用户 | PoC 未接后端 |
| 双通道白板 | 设计者 | 高频交互（拖拽/聊天） | 单画布数十~数百元素 | 原型 20 元素实测通过 |
| Agent 改图 | 系统（用户触发） | 复杂意图时；每步多 tool 调用 | 每任务步数上限兜底 | 未接后端 |
| 校验自修正 | 系统（每次出图必跑） | 每出图 1~3 轮 | 单轮 issues 数不定 | 未接后端 |
| 会话记忆 | 系统 | 每会话持久化 | Redis 单实例 | 未落地 |

> 量级中"当前实测"列空白项 = 对应能力尚在目标架构阶段、真实代码未重建（见 `architecture.md` 风险与演进）。
