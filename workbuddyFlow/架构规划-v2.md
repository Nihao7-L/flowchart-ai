基线现有 13 个类（controller 1 / service 3 / client 2 / model / config）全部保留为种子，

```
io.github.nihaoljx.flowchart
├── controller/      REST + SSE 接口层（只做参数校验和编排，不写业务逻辑）
├── service/         生成编排：Prompt 组装 → LLM 调用 → 解析 → 校验 → 修正循环
├── llm/             LLM 接入层（原 client 改名）：Provider 抽象、Gateway 网关、路由降级

├── rag/             检索增强：结构感知切分、向量化、召回（阶段2 再建）
├── tools/           工具注册与执行：function calling 的工具菜单和执行器（阶段3 再建）
├── agent/           Agent 规划与执行：真 ReAct 循环（阶段4 再建）
```

## 四、前端架构（2026-09-11 修订：React Flow → Excalidraw）

- 画布：**`@excalidraw/excalidraw` 手绘白板**，取代 React Flow；React 18 + Vite + TS + Zustand 做外壳与状态
- **双通道协作**：前端持 `model` 渲染镜像；人类在画布拖拽/手绘 与 AI 聊天命令改图，二者都改**后端持有的同一份 `model`（IR）**；人类 `onChange` 坐标经 `PATCH /api/model/positions` 回写后端，AI 改图也汇到同一份 model，互不覆盖
- **IR（中间表示）/ Graph Spec**：LLM/Agent 只出"节点+边、无坐标"的语义；坐标由前端 `layout()` 算、手绘样式由 Excalidraw `convert` 兜底——**LLM 不出像素、不出 Excalidraw JSON**
- **Agent 返回协议（双协议）**：
  - 增量 `ops`：对话里"加节点/连线/改名/标色"→ 一串 `{tool, args}`，前端 `applyTool` 叠加
  - 全量 `spec`："换一个复杂的"整图替换 → `{nodes, edges}`（无坐标），前端整体重绘
- **Diagram Tools = 自研 MCP**：前端的 add/connect/update/delete/reset 工具，与后端 LLM tool calling（ToolRegistry + ToolExecutor）同构；`interpret()`（规则解析）后续换成后端 AgentPlanner 的 LLM 调用
- **先设计后编码**：阶段6 先出 HTML 设计稿（色板 / 布局 / 组件规范，含双通道交互），用户确认后再实现
- 前端状态统一进 Zustand store 并做 localStorage 持久化

## 七、Git 工作流约定

- `main` = 稳定可运行版；开发在 feature 分支（或继续用 reframing），完成后 merge 回 main
- commit message：`feat|fix|chore|docs: 动词开头的中文描述`
- **提交前必须 run-verify 绿**——这条同时约束人和 Agent
- application.yml / 阶段总结与规划.md 永远本地保留不入库（.gitignore 已固化）

## 八、不变式（任何人与 Agent 都不得破坏）

1. 所有 LLM 调用必须经 `llm/` 网关收口，业务代码不得直连 Provider
2. 出图必须走结构化 JSON 契约 + 校验循环，禁止裸文本直出
3. application.yml（含明文 key）永不入库；用户已明确接受明文本地保留，不要再提示改环境变量
4. 交付前 run-verify 必须绿——没跑验证的代码不得说"完成"
5. 改约束先改本文档或 docs/，再改代码；文档与代码不一致时以文档为准修代码
