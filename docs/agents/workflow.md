# workflow.md — 一次任务的标准流程

> 只回答一个问题：**一个任务从开工到收尾，每一步做什么、产出什么。**
> 读它的时机：每次开工前。人（用户）与 Agent 共同遵守。

## 一、四拍

### ① 会话开场：先读地图

人对 Agent 说：

```
先读 AGENTS.md，按索引读完 docs/agents，复述你要遵守的约束再动手。
```

Agent 输出：约束复述（重点是三条硬规矩与八条不变式）+ 等待任务。
**这一步替代"每次口头交代规矩"，是跨会话不失忆的唯一手段。**

### ② 开工前：计划先落盘（人在这一拍"盯 Plan"）

Agent 在 `docs/exec-plans/active/vX-N.md` 写出六项：

1. 目标（一句话、可验证）
2. 边界（只允许改哪些目录/文件）
3. 前置任务
4. 步骤（编号）
5. **验收口径**（怎么算成功，必须是可执行的标准）
6. 覆盖测试数据（正常 / 边界 / 异常）

人确认后才准动代码。要改就改计划文件，不改口头约定。

### ③ 执行中：边干、边验、边记

改代码 → 跑 `run-verify.ps1` → 往 `docs/exec-plans/activeLog.md` 追加一行（时间 / 任务号 / 动作 / 证据）。
验证不过就回到上一步，Agent 看输出自己改，**不要问人**。

### ④ 收尾：归档与勾账

计划文件移入 `docs/exec-plans/completed/` → 勾掉 `docs/架构规划-v2.md` 对应项 → 提交。
提交信息：`feat|fix|chore|docs: 动词开头的中文描述`。**verify 绿才允许提交。**

## 二、编排写代码的 Agent（五条规程）

| 规程 | 做法 | 对应六层 |
|---|---|---|
| 入口唯一 | 新会话第一句固定发下面的话术模板 | L1 信息边界 |
| 计划先落盘 | 没写 exec-plan 不许改码 | L3 执行编排 |
| 证据交付 | "完成" = run-verify 输出 + activeLog 一行 | L5 评估观测 |
| 记忆外置 | 上下文靠 activeLog 尾部恢复，不靠模型记忆 | L4 记忆状态 |
| 红线前置 | 禁令写在 `engineering.md` 第五节 | L6 约束恢复 |

**话术模板（每次开新会话直接粘贴）**

```
先读 AGENTS.md 和 docs/agents/*，复述你要遵守的约束再动手。
任务：v2-N。
第一步：写 docs/exec-plans/active/v2-N.md（目标/边界/步骤/验收口径），等我确认。
完成后必须附 run-verify 输出，并在 activeLog.md 追加一行带证据的记录。
```

## 三、错误记到哪（两类 Agent 分开，别混）

| 谁犯错 | 记到哪 | 变成什么 |
|---|---|---|
| 产品里的 Agent（ReAct / 工具 / 校验 / 会话） | `tech-debt-tracker.md` 或路线图验收口径 | 变成任务 |
| 写代码的 Agent（AI） | `engineering.md` 第五节 | 变成约束 |

## 四、收尾自检清单

- [ ] `run-verify.ps1` 绿
- [ ] `activeLog.md` 有带证据的一行
- [ ] 计划文件已移入 `completed/`
- [ ] `docs/架构规划-v2.md` 对应项已勾
- [ ] `features.md` 状态列已更新
- [ ] `git status` 里没有 `application.yml`

## 五、active / completed / activeLog = 状态机 + 外置记忆

**状态机**：每个计划文件顶部必须有一行状态，取值只有四种——

```
> 状态：待审 | 进行中 | 阻塞 | 完成
```

- `active/` 放正在跑的任务：**一个任务一个文件**，文件名 `vX-N-短名.md`
- 完成后 `git mv` 到 `completed/`，在文件顶部加一行完成结论（**原计划内容不改**，那是给未来复盘看的）
- `activeLog.md` **只追加，不修改历史行**，格式：`MM-DD HH:mm vX-N 做了什么 → 证据`

**多 Agent 并行时**：各自写自己的计划文件，互不覆盖；activeLog 追加式写入天然不冲突；谁收尾谁负责移文件与勾账。
会话被压缩或换新会话后，恢复上下文只需读 `activeLog.md` 最后几行 + `active/` 里的状态行。

## 六、新知识该写进哪份（每份只回答一类问题）

| 新知识 | 写进 |
|---|---|
| 项目阶段、定位、已定决策变了 | `project.md` |
| 包边界、调用关系、数据流 | `architecture.md` |
| 功能增删、功能状态变化 | `features.md` |
| 命令、环境坑、操作禁令 | `engineering.md` |
| 流程、话术、编排规程 | `workflow.md` |
| 路线图任务（编号、验收口径） | `docs/架构规划-v2.md` |
| 产品里 Agent 的缺陷 | `docs/exec-plans/tech-debt-tracker.md` |

**不属于以上任何一类的知识，先别写**——少即是多，每多一句废话就多一分理解偏差。
