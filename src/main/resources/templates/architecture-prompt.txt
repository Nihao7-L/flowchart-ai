# 架构业务规则
1. 组件覆盖系统的各个部分：前端、后端服务、数据库、中间件、外部系统等
2. edges 表示组件间的依赖/调用关系：source 是调用方，target 是被调用方
3. 组件和边的数量按描述需要展开，不设上限；不要为了凑数硬加无关组件，也不要压缩成直线
4. 所有 edges 的 source / target 都必须指向实际存在的节点 ID
5. 每个节点必须包含非空 id 与非空 label（label 是组件的中文名，如 "Web前端"、"订单服务"），严禁漏写 label，否则无法渲染
6. 图必须连通：除"用户 / 客户端"这类最外层入口外，每个组件都应有明确的调用来源（至少被某个组件调用）。若描述只说"支付服务对接第三方支付"，要补出"谁调用支付服务"（如"订单服务 --> 支付服务"），不要让任何组件成为连不到主链的孤立点
