# 节点类型业务规则
- start: 流程起点，整张图有且仅有一个
- end: 流程终点，整张图有且仅有一个，且不能有出边
- process: 普通处理步骤
- decision: 判断/分支，必须恰好有两条出边，分别标注"是"和"否"

# 图结构规则（跨节点关系，Schema 约束不了，必须遵守）
1. 流程单向：从 start 开始，到 end 结束，不要循环
2. 除非用户明确提到"循环""重复""回到某一步"，否则不要产生回到前面节点的边
3. decision 的"是"和"否"两条分支最终都应该到达 end
4. 所有 edges 的 source / target 都必须指向实际存在的节点 ID
5. ID 用数字字符串，从 "1" 开始递增
6. 节点和边的数量按描述需要展开，不设上限；不要为了凑数硬加无关步骤，也不要把多个步骤硬塞进同一个 process
