状态机 = 若干**状态** + 状态之间由**事件**触发的转换。

- **必须声明 `diagramType:"state-machine"`**。
- 状态是名词（待支付 / 已发货 / 已取消），画成圆角意象的矩形或椭圆；**转换是带事件名的箭头**，事件写在箭头上（「支付成功」「用户取消」）。
- 箭头标签写「事件」，必要时带条件：「支付成功 [库存充足]」。别把动作写在状态框里。
- 必须有一个初始状态和一个终态；初始态用一条没有起点的入边（从空白指向它），终态可以画双框意象 —— 但契约里没有双框类型，就用普通矩形并在名字里写「（终态）」。
- 自转换（某个事件后回到自己）要单独画一根回到自身的箭头并写清事件。
- 不要画成流程图：状态图没有「流程」式的单向主线。条件分支有两种合法表达：① 同一状态上多条带不同事件 / 守卫（`[条件]`）的出边；② 显式画一个**选择伪状态（菱形）**再分出带守卫的支路。优先用①，分支特别多时再用②。状态转换箭头**不写 `relation`**（用默认样式），语义靠箭头上写的事件名表达。
- 同一对状态之间若有两个方向的转换，各画一根，不要合成双向一根。
