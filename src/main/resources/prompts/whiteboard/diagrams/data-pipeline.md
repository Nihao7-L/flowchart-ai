数据流水线 = 数据从源头经过一串处理环节，最终落到目的地。

- **必须声明 `diagramType:"data-pipeline"`**。
- 环节（采集 / 清洗 / 转换 / 聚合 / 入库 / 可视化）依次排成一条主链，方向从源头到目的地，不要来回。
- 数据源（MySQL binlog / 日志文件 / 第三方 API）与目的地（数仓 / 报表 / 特征库）都用节点表示，并在 label 里注明它是源还是目标。
- 连线一律用 `relation:"data"`（这是数据在流，不是服务在调用）；批处理与流式的区别写进连线标签（「实时流」「T+1 批量」）。
- 分支（一路数据同时供两个下游）各画一根线，不要合并；分叉后的两条链各自走完。
- 阶段（采集层 / 计算层 / 服务层）用 `group` 表达。
