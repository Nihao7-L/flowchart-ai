架构图 = 分层摆放的组件 + 组件之间的依赖 / 调用。

- **必须声明 `diagramType:"architecture"`**。
- **每一层是一个 `group`**（接入层 / 业务层 / 数据层 / 中间件），组件的 group 写它所在的层名 —— 层靠 group 生成，你不要自己画层框。
- 层间连线方向体现依赖：上层调下层（网关 → 服务 → 数据库）。同层之间尽量少连；同层的横向调用要写清它是什么（「服务发现」）。
- 区分调用与数据流：请求调用用 `relation:"call"`，数据读写用 `"data"`，异步消息用 `"async"`，部署依赖用 `"dependency"`。
- 同类中间件（Redis / MQ / ES）归到同一层的同一个 group，不要散落在图各处。
- 组件名写「服务名」即可（订单服务 / 支付服务），不要把技术栈括号塞进每个节点（会撑宽节点、压坏版面）；技术栈信息放分组名或标题里。
- 不要为了让图有框而硬凑分区：分不分层取决于需求本身的层次，没有层次就别分层。
