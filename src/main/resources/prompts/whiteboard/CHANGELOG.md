## 10.15.0 (2026-10-17)

**内核瘦身到一半 + 图型模板扩到 25 种 + 图型与版面解耦**

- **内核 md 6531B → 3223B（-50.7%）**，system 块 9888B → 6580B。做法：图型专属规则全部迁出（插画 / 伪 3D 那条最长的规则迁成 `diagrams/illustration.md`）；压缩重复表述 —— 输出格式原来两处重复讲「不夹散文」，submit_scene 冻结说了一遍半，过程段四条各带一段解释。
- **图型模板 1 → 25 种**：sequence / flowchart / mindmap / org-chart / state-machine / er-diagram / class-diagram / use-case / activity-diagram / gantt / timeline / fishbone / decision-tree / swimlane / architecture / network-topology / data-pipeline / user-journey / matrix-quadrant / venn / concept-map / fault-tree / tree-structure / circular-flow / illustration。每种都写清「这是什么图 + 节点怎么建 + 连线什么语义 + 常见画错」。
- **图型（diagramType）与版面（layout）解耦**（代码改动）：`DiagramTemplate` 新增 `layout` 字段（默认 generic），`DiagramPromptRegistry.layoutOf/isKnown`；`SubmitSpecTool` 的 diagramType 合法值改为「布局家族 ∪ 已注册图型模板」，排版按 `layout` 路由。**否则每加一种图型都要写一套排版器**，且模型照模板声明了 gantt 也会被判「未知图型」打回修正轮 —— 这是「加图型」此前最大的隐性成本。
- 关键词路由按最长匹配，长词压短词（「组织架构图」压「架构图」、「跨职能流程」压「流程图」）。

## 10.14.0 (2026-10-17)

**目标：提示词按图型分层 + 模板热加载。加一种图 = 丢一个 md 文件，不再动内核。**

背景：内核 md 顶到字节闸门（9987B / 上限 10000B，只剩 13B），加任何图型规则
都得从通用规则里挤字节 —— 「加图型」和「改通用规则」互相绑架。借鉴 tldraw 的
PromptPart 拼装、Claude Code Skills 的条件触发模板、Langfuse 的 label 部署、
JPrompt / Spring AI Lab 的 WatchService 热加载，落成三层：内核（共用）+ 契约
（schema 派生）+ 图型模板（按需注入）。

- **内核瘦身**：`system-prompt.md` 删掉「时序图必须声明 diagramType:"sequence"」这条
  专项规则，替换成一句通用指引「下面若给了『## 图型模板』段就按它声明 diagramType」；
  时序图规则整体迁到 `diagrams/sequence.md`。
- **新增 `prompts/whiteboard/diagrams/`**：一种图一个 md，frontmatter 写
  `diagramType / version / title / keywords`。
- **新增 `prompt` 包**：`DiagramPromptRegistry`（扫描 classpath 内置 + 可选外部目录
  注册、确定性关键词路由、WatchService 热加载、单文件解析失败保旧）、
  `DiagramTemplate`、`PromptText`（注释剥离口径与内核统一）。
- **装配顺序**：内核 + 契约 + 图型模板。内核与契约是全请求共享的稳定前缀，
  图型段是唯一变量 —— 这样 KV-cache 命中率最高（图型段插中间会切碎公共前缀）。
- **路由是确定性的**：按 keywords 在用户原话里做包含匹配，命中多个取最长关键词。
  刻意**不加** LLM 分类那一跳（要多付一次调用，SLA 是百秒级）。
- **字节闸门拆两档**：内核块仍守 10000B；新增「内核 + 最大图型模板」守 12000B。

**目标：语义路径补上「颜色/标题」表达能力，把「用户点名了颜色」这条逼模型回退手写坐标的旁路堵死。**

背景（2026-10-16 五张参考图实测）：v10.10.0 虽已要求结构化图表一律 submit_spec，但 spec 当时

（3 节点流程图实测 5.3s）。结论：**颜色是语义（这一层是什么），该留在 spec 里用有限词表表达；
坐标才是几何，必须拿走**。

配套代码（同批）：
- `SubmitSpecTool`：节点新增 `color`（具名枚举，填充 + 同色系深一档描边）；spec 新增 `title`

- 顺带修一个工具 schema 缺陷：`enum: List.of(SHAPE_TYPES)` 把 Set 当单元素包成嵌套数组

用户处置（2026-10-11）：「1、2 补回，其它的就按我改过的 system prompt 来，测试代码对齐它」。即：
- **补回 ①** L0 治理头、**补回 ②**「执行过程四步都是内部思考，不要输出到结果里」；

补回 ② 的理由（本次最重要的发现）：这句治的是「节名与措辞像输出模板 ⇒ 模型把内部执行过程照抄进 JSON」，
而它在 `src/main` 与 `src/test` 里 grep 命中数**都是 0** —— **没有任何测试守着它，属静默丢失型回归**。

CHANGELOG 三元组断链。注意治理头是 HTML 注释，运行时被 `stripComments` 剥掉 ⇒ **发给模型 0 字节，不占预算**。

**已知代价（记录在案，是取舍不是 bug）：**
- 「归属与分区」（`图形数 > 15 时先按模块打 group` / `框的 name 必须与模块 group 逐字相同`）从 md 移除后，

  LLM 不再被要求主动打 group，frame 认领退化到启发式路径。契约段仍说明「框的成员由后端按
  『图形的 group 与框的 name 同名』算出」，但**不再声明何时该打 group**。
- 「增量保护」（`仍要输出全量 elements`）移除无碍：编辑模式下由 `PromptService.modifyRulesBlock()`
  在运行期注入（`PromptService:497`「你输出的是**修改后的完整场景**（全量 elements），不是差异片段」）。
- 「一致性」（同主题 / 同会话配色与风格统一）移除后**无任何兜底**，属观感风险，未做代码侧补偿。

测试代码同步对齐（三处，原则：**不让测试与 md 口径互相绑架**，护栏降级要显式记在注释里）：

  —— 守住「不许再出现禁令」，但**不再要求 md 必须写某句正面表述**。
- `PromptServiceContractTest.v580EssentialRulesKept`：删除 `assertTrue(block.contains("全量 elements"))`
  （该文案只存在于运行期注入的 modify 块，静态层已无）。`freedraw` 断言保留 —— 它由契约段兜住。
- `PromptServiceTest.testModuleGroupingGuidance`：删除阈值（`ScenePlanner.MODULE_THRESHOLD`）与
  「逐字相同」两条断言；`group` / `children` 两条保留（契约段仍覆盖）。

字节核算：md 文件 6306 B / strip 后 5530 B / system 块 **8887 B**（闸门 10000 B，余量 1113 B）。

## 10.8.0 (2026-10-10)

**目标：把「freedraw 默认不开」的限制改成「可用」—— 消除 md 与代码的口径冲突**

背景（用户拍板）：md 原写「freedraw（自由手绘）默认不开，只有用户明确要手绘 / 涂鸦时才用」，
但代码侧**早就把 freedraw 当一等能力**：

- 后端 `GraphValidator` 有专门的 `validateFreedraw`（freedraw 是完整受支持的类型，
  不是"勉强放过"）；`PromptService` 的类型白名单里也有它；
- 前端 `frontend/src/lib/sceneAdapter.ts` 写着「**freedraw（手绘路径）现在是白板的一等能力：
  用户说「画几笔」「圈一下」时 LLM 可以输出 freedraw**」，并专门处理了它
  "转换后 width/height 是 undefined"、"angle 字段缺失"、"pressures 与 points 等长"这些细节。

⇒ **只有 md 在唱反调**，而且这条限制**没有机器判据**：2026-10-10 实测「给我画一只猫，要那种很像真的」
出了 **20 个 freedraw**，校验器一个都没拦（它只管 freedraw 本身合不合法，不管"允不允许用"）。
**只写在 md 里、没人检查的规则等于没有** —— 与其留一条自欺的禁令，不如把口径摆正。

改动要点：
- 「# 规则与边界 → ## 边界 → 能力限制」条：`freedraw（自由手绘）默认不开，只有用户明确要手绘 / 涂鸦时才用。`
